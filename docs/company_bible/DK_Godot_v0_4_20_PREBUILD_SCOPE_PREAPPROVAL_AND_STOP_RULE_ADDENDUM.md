# DK Godot v0.4.20 Prebuild Scope, Preapproval, and Stop Rule Addendum

**Date:** 2026-07-13  
**Status:** Mandatory workflow rule

Before any future build, patch, hotfix, package, ZIP, EXE build, replacement file generation, or equivalent implementation work, the assistant must first tell Derek:

1. what will be done;
2. why it will be done;
3. what files or systems may be touched;
4. risks;
5. validation plan;
6. documentation/handoff requirements;
7. expected output package name/version.

Implementation must not begin until Derek approves that scope or gives an explicit build/patch command after the scope has been stated.

If Derek says stop, all build/tool/package work stops immediately. The assistant must answer plainly instead of continuing silent work.
