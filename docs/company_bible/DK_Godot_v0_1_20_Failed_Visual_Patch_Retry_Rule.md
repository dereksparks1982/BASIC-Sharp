# Company Bible Addendum - v0.1.20 Failed Visual Patch Retry Rule

When Derek reports that a patch did not visibly take, the next patch must re-carry the failed visual/system change and implement it more defensively. Do not assume a changelog entry means the feature actually showed up in play.

For visual/game-feel changes, include a visible verification marker or unmistakable gameplay presentation whenever practical.

This rule reinforces existing DK practice:

- requested work is done in the next build/patch unless Derek says to wait;
- failed patch work is retried, not ignored;
- documentation must explain what failed, what was changed, and how the retry is more defensive.
