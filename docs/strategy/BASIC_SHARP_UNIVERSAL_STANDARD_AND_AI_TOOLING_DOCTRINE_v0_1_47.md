## North star

BASIC# / BSharp aims to become a universal creator-facing programming standard: one readable language for websites, apps, games, tools, automation, and business systems.

The long-term ambition is not only to be easier than existing languages. The ambition is to become portable enough, validated enough, and eventually fast enough that companies can choose BSharp instead of juggling many specialized languages for ordinary creation work.

## AI-era language purpose

BASIC# is being designed for a world where humans and AI systems build software together.

The strategic advantage is shared readability:

```text
human intent
-> BASIC# source
-> validated BSharp IR / BSharp Bytecode
-> web, app, game, tool, or server output
```

A good BASIC# program should be understandable to a non-programmer, generatable by an AI assistant, inspectable by validators, and compilable into dependable platform output.

## Compatibility before replacement

BASIC# must meet the world before asking the world to meet BASIC#.

For web work, the staged rule is:

```text
BASIC# source
-> normal HTML for structure
-> normal CSS for style
-> normal JavaScript for browser behavior
-> WebAssembly or native targets later when earned
```

A BASIC#/BSharp-native browser is a future ecosystem idea only after web export, creator demand, and production proof exist. It is not part of the current self-hosting runway.

## Performance before hype

BSharp must treat performance as a first-class requirement, but it must not make empty speed claims.

The path to speed is staged:

```text
BASIC# source
-> BSharp IR
-> BSharp Bytecode
-> BSharp VM
-> optimized bytecode
-> native and WebAssembly-style backends later
```

Every layer should avoid trapping BASIC# as a slow wrapper when a future faster target can be earned through validation.

## Sponsorship posture

OpenAI or another AI tooling sponsor should be approached only with proof, not smoke.

The strongest pitch is:

```text
BASIC# is a plain-English programming language for the AI era:
a creator-facing source language that humans can understand,
AI can generate safely,
and compilers can validate into games, apps, websites, and tools.
```

A future sponsor packet should include:

- one-page pitch;
- technical summary;
- roadmap;
- demo script;
- validation proof;
- terminal evidence;
- clear request for API credits, tooling support, founder attention, or partnership discussion.

This doctrine authorizes documentation and roadmap positioning only. It does not authorize licensing work, funding claims, OpenAI outreach, web implementation, browser work, or replacement marketing in v0.1.47.
